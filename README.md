\#RAG-QE-HyTrans: English–Kannada Low-Resource Machine Translation



This repository provides the reproducibility package for the paper:



\*\*RAG-QE-HyTrans: A Quality-Aware Retrieval-Augmented Hybrid Framework for Low-Resource English–Kannada Machine Translation\*\*



\## Overview



RAG-QE-HyTrans combines:



\- NLLB-200 distilled 600M baseline translation

\- LoRA-based parameter-efficient adaptation

\- FAISS-based semantic translation-memory retrieval

\- Fixed-threshold RAG-Hybrid selection

\- Validation-selected RAG thresholding

\- Reference-free quality-aware hybrid selection



The central finding is that retrieval augmentation is useful only under strict reliability control, while LoRA-NLLB provides the most stable improvement.



\## Dataset



The dataset is not redistributed in this repository.



The experiments use the Kannada (`kn`) subset of the AI4Bharat Samanantar corpus from Hugging Face:



\- Dataset: `ai4bharat/samanantar`

\- Configuration: `kn`

\- Language pair: English–Kannada



Two corpus settings are used:



| Setting | Initial pairs | Final filtered pairs | Train | Validation | Test |

|---|---:|---:|---:|---:|---:|

| 5K | 5,000 | 4,932 | 3,945 | 493 | 494 |

| 50K | 50,000 | 49,553 | 39,642 | 4,955 | 4,956 |



\## Main 50K Results



| Method | BLEU | chrF++ |

|---|---:|---:|

| Baseline NLLB | 9.6481 | 37.6486 |

| LoRA-NLLB | 10.2429 | 37.9050 |

| RAG-Hybrid 0.70 | 7.6484 | 31.4821 |

| Test-best RAG 0.99 | 10.2833 | 37.8653 |

| Validation-selected RAG 0.98 | 10.2716 | 37.8415 |

| Quality-aware hybrid | 10.2242 | 37.8886 |



Note: Test-best RAG 0.99 is reported only as threshold sensitivity analysis. The methodologically valid final RAG result is validation-selected RAG 0.98.



\## Reproducibility Status



The original cloud pod used for the experiments was terminated after completion. This repository is therefore structured as a clean reproducibility package. Large generated artifacts such as raw data files, model checkpoints, LoRA adapters, FAISS indices, and sentence-level translation outputs are not stored in GitHub and must be regenerated by running the scripts.
